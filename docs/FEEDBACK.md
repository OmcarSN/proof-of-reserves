# Feedback Loop Documentation

## Feedback Collection Methodology
We collect user feedback primarily through a structured Google Form and direct community engagement. The form includes specific questions targeting different aspects of the application and optionally asks for the user's wallet address to verify their interaction with the Midnight Preprod network.

## Feedback Categories
We categorize incoming feedback into four main areas:
- **UI/UX**: Navigation, visual design, clarity of instructions, and overall user experience.
- **Functionality**: Bugs, broken links, wallet connection issues, and proof verification errors.
- **Trust & Security**: Clarity of the ZK proofs, confidence in the solvency verdict, and data privacy concerns.
- **Feature Requests**: Suggestions for new features, additional supported wallets, or expanded dashboard analytics.

## How We Prioritize
1. **Critical Functionality & Security**: Bugs preventing wallet connection, proof verification, or network interaction.
2. **High-Impact UX**: Changes that significantly improve user understanding of the ZK mechanics or core flows.
3. **Feature Requests**: Evaluated based on development effort and alignment with the project's core goals.
